# Правила сборки итогового main.py

## Главный принцип

- При переносе заданий коллег в `main.py` сохранять код коллег максимально дословно.
- Не улучшать, не переписывать и не упрощать код по своей инициативе.
- Не менять стиль, названия переменных, комментарии, кавычки и форматирование без необходимости.
- Не удалять закомментированный текст задания и комментарии коллег.
- Над каждым блоком задания оставлять комментарий с номером задания, например:
  `# задание 1_01`.

## Что можно менять

- Пути к файлам данных, чтобы код работал внутри общего проекта.
- Подключение очищенных данных после выполнения общей очистки.
- Минимальные строки, которые мешают запуску.
- Явные ошибки в источниках данных только после сообщения пользователю или его подтверждения.

## Что нельзя менять без согласования

- Логику расчётов.
- Выбор методов анализа.
- Структуру вывода, если она не ломает запуск.
- Комментарии коллег.
- Названия промежуточных таблиц и переменных.
- Код задания на более красивый или более правильный вариант.

## Очистка данных

- В начале итогового `main.py` должен быть код очистки из `cleaning.py`.
- Очистка не должна запускаться повторно при каждом задании, если очищенные файлы уже созданы.
- Если нужные файлы есть в `cleaned_data`, задания должны читать уже выгруженные очищенные данные.
- Повторно запускать очистку нужно только если очищенных файлов нет, они неполные или пользователь прямо просит пересоздать данные.
- После очистки задания читают данные из `cleaned_data`.
- Для таблиц из Excel использовать `cleaned_data/company_data_cleaned.xlsx` и нужный лист.
- Если файл коллеги ожидает другой очищенный файл, сначала проверить, есть ли он в текущем процессе очистки.
- Если источник данных в коде противоречит тексту задания, сначала сообщить пользователю и уточнить или дождаться подтверждения.

## Проверка

- После добавления каждого задания проверять синтаксис `main.py`.
- После изменения пути или подключения данных запускать `main.py` или затронутый блок, если это возможно.
- Если полный запуск долгий, сообщать об этом и не считать таймаут ошибкой без повторной проверки.

## Результаты заданий

- Таблицы сохранять в `results/task_...` в формате `.csv`.
- Графики сохранять в `results/task_...` в формате `.png`.
- Если в коде коллеги нет сохранения результата, можно добавить сохранение без изменения расчётов.
- В консоль выводить относительный путь к созданному файлу, например:
  `Таблицю збережено: results\task_1_03\average_check_by_store.csv`.
- Для графиков выводить:
  `Графік збережено: results\task_...\file.png`.

## Git

- Не делать commit, push, merge или Pull Request без прямой команды пользователя.
- Перед commit проверять `git status`.
- Не добавлять в Git `cleaned_data`, `results`, `.db`, большие исходные данные и локальные служебные файлы.
